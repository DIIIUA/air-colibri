## Механизм

`src/general_speculation.py` подаёт текущий токен и до трёх черновых продолжений в
обычный послойный `_forward_step`. Основная модель решает, сколько из них принять.
Каждый уже загруженный слой обрабатывает проверяемые строки последовательно
(`rowwise_verification.py`), чтобы сохранить арифметику обычного decode. Весовой
набор не размножается по числу токенов. Это повторное использование загрузки слоя;
зависимые слои не начинают считать до готовности своих входных активаций.

Отклонённый attention-хвост обрезается. Для recurrent/sliding cache сохраняются
состояния между строками и восстанавливается последняя принятая граница. Для
поддержанного снимком состояния предусмотрен резервный повтор только принятого
префикса. Оценка удерживаемого состояния ограничена 64 МиБ: глубина уменьшается
до обычного decode при нехватке бюджета. Это дополнительный бюджет проверки;
он не ограничивает весь пользовательский KV-контекст.

Во время проверки фиксируется размещение вычислений. Подготовка GPU продолжает
получать уже прочитанные неизменяемые веса; прогрев использует сохранённую карту.
Только принятые маршруты обновляют историю карты. Ошибка GPU-подготовки не меняет
устройство посреди проверки: CPU принимает состояние на следующей границе.
Исходная вероятность в thought buffer сохраняется. Прямое вмешательство в
recurrent state (`rec_anchor_lambda > 0`) переводит этот цикл в однотокенный режим.

## Заводская голова

`src/native_mtp.py` сейчас реализует **Qwen3.5 text**. Только веса головы живут
на CPU (обычный предел 128 МиБ), её KV растёт с разрешённым контекстом. Embedding
и словарная проекция используются из основной модели. Нет второй копии backbone,
целого отображённого checkpoint или требования держать все слои в RAM/VRAM.
Голова может работать с CPU-путём и общим CPU/GPU-путём; проверяет всегда основная
модель. Наличие адаптера не означает, что любые чужие MTP-веса совместимы.

У имеющегося GGUF Qwen3.5-0.8B заводских MTP-тензоров нет. Стенд
`benchmarks/extract_native_mtp.py` прочитал только 15 `mtp.*` диапазонов официального
`Qwen/Qwen3.5-0.8B`, revision `2fc06364715b967f1860aea9cf38778875588b17`.
Получено **40 905 728 байт параметров (39.01 МиБ)**. Полный HF-checkpoint не скачивался.
Файл: `data/native-mtp/qwen3.5-0.8b.safetensors`; рядом `.provenance.json` с SHA256
отдельных тензоров, revision и исходными смещениями. Имеющиеся модели не изменялись.

Без совместимой головы `auto` использует **prompt lookup**, а `native` явно
сообщает об отсутствии головы. Эти режимы не отождествляются в статусе и метриках.

## Отсечение

`src/route_exclusion.py` работает с известными output-weighted HF Granite/OLMoE.
Эксперт с **точно нулевым** фактическим коэффициентом получает sentinel до чтения
его весов. Остальные выбранные router эксперты остаются обязательными. Состав
невыбранных экспертов хранится как дополнение к текущему маршруту, без полного
bitmap модели. Неактуальная необязательная подготовка отменяется только для
того же слоя и шага; следующий шаг может снова выбрать исключённого эксперта.

Это безопасная область отсечения, а не доказательство того, что ранняя вероятность
разрешает навсегда выбросить произвольные плотные веса. Обычный router уже
не читает невыбранных экспертов; его существующая экономия не является новым
ускорением этой итерации. На моделях без подходящего контракта отсечение не включается.

## Реальный Qwen-прогон

`D:\Air-Colibri Storage\development_20261118\native_qwen_live_1.json`:
GGUF Q4_K_M, внутреннее исполнение Q6, RTX 3060 Ti, шесть CPU-потоков. Для обеих
сторон принудительно заданы ноль resident layers, три GPU-слота и RAM-кэш весов
128 МиБ; пик кэша 114.62 МиБ, были реальные вытеснения. Глобальные веса, активные
слоты, KV и голова учитываются отдельно от этого кэша. Это не предел всего процесса.

Контроль и native дали **одинаковые 8 + 4 токена**, включая продолжение из
сохранённого cache без повторного прогона старого backbone. Предложено 9 draft
токенов, принято 4; 6 verification batches, 3 восстановления recurrent state,
5 отброшенных строк. Decode backbone passes: **10 → 6**. Оценка пика снимков:
60 751 872 байт, ниже 64 МиБ. Размер/mtime исходных весов не менялись.

|---|---:|---:|---:|
| 7 decode-токенов после prefill | 24.865 с | 24.163 с | 7 → 5 |

## Проверка совместных границ

`granite_streamed_final_3.json`: настоящий HF Granite 1B, checkpoint 2 669 283 096
байт, внутренний Q6. Принудительно ноль resident layers, три dense-слота, RAM cap
128 МиБ и экспертный бюджет 128 МиБ до объединения арен. Общая weight arena
составила **121 405 440 байт (115.78 МиБ)**: **95 слотов для 768 экспертов**.
Глобальные веса, KV, рабочие временные тензоры и RAM учитываются отдельно.
Пик RAM-кэша слоёв 42 008 576 байт, были 464 / 345 вытеснений у контроля / lookup.

Все **8 + 4 токена совпали**; 5/7 drafts приняты, 4 verification batches,
2 отброшенные строки и 48 незафиксированных route rows (24 слоя × 2 строки).
Decode backbone passes **10 → 5**. Fingerprint исходной FP32 вероятности и
первоначальной карты одинаков у контроля и lookup после обоих запросов.
Подготовленные веса использовались во всех трёх областях: 431 / 470 / 511
consumptions, включая отдельно учитываемые verification reads. C: ноль used
и reserved bytes; активных reader leases на момент отчёта нет.

В обоих настоящих Granite-прогонах **точно нулевых route coefficients не было**.
Новая zero-route оптимизация доказана синтетическими read-callback тестами;
экономия обычного top-k router не записывается в её новое ускорение. Реальные
маршруты вне прогноза продолжали загружаться.

Decode-времена контроля: 40.192 / 48.996 с; lookup: 41.358 / 6.030 с. Полный цикл

цикла. Перечитывание/переупаковка при малом кэше и дорогой prefill требуют дальнейшей
оптимизации. Это проверка bounded execution на HDD, не сертификация ускорения.

`spec_target_3.xml`: **12 passed**. Native-адаптер проверен полностью на CPU
на маленьком синтетическом Qwen с продолжением cache; веса этой тестовой головы

## Повторение и границы

`benchmarks/general_speculation.py --case qwen --tokens 8 --output PATH` сравнивает
контроль с заводской головой; `--case granite` — lookup вместе с динамической
ареной, прогревом и thought anchor. Каждый запуск пишет хеши исходников, токены,
времена, параметры кэша, метрики маршрутов и проверку размера/mtime checkpoint.

В обычном CLI: `--speculation native --mtp-head data/native-mtp/qwen3.5-0.8b.safetensors`.
`--device cpu` разрешает явный CPU-режим. `--speculation off` отключает drafts,
`--no-region-pruning` отключает новые scoped exclusions.

Нативные головы остальных семейств, произвольное плотное probability-pruning,
общая KV/SSM-арена и разрезание больших операторов на кубики не реализованы этой
итерацией. Модели 90–350 ГБ не проверялись. Размер checkpoint не является
критерием запрета; ограничения отдельных рабочих операторов пока сохраняются.

Общий draft/verify цикл сейчас использует обычный chunked prefill. Универсальный
`prefill_wavefront` проверяется отдельно с `speculation="off"`; его совместная
оптимизация с этим циклом ещё не выполнена.

Проверка строк разрешена только для известных decoder/cache-контрактов. Остальные
семейства продолжают однотокенный streamed decode; это явно видно по
`batching_supported=False` и `decoder_contract_plain_steps`. Поддержка запуска
модели и поддержка ускорения через batching являются отдельными возможностями.
